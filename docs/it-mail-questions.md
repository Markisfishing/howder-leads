# 寄信給客戶：要請 IT 確認的事（2026-11-18）

> 用途：決定系統正式寄信給客戶要怎麼接公司的對外信箱。下方「可以直接傳給 IT 的訊息」可整段複製。
> IT 回覆後，依最下面的對照表決定做法，結果記進 `PROGRESS.md`（M2-26）與 `CHANGELOG.md`。

## 可以直接傳給 IT 的訊息

> 您好，業務部的「潛在客戶邀請信系統」之後要用公司對外信箱寄信給客戶。系統只會寄出業務逐封核准過的信，不會讀取任何人的信箱。想請教以下幾點：
>
> 1. 公司對外信箱是 **Microsoft 365（公司網域，例如 @公司網域）**，還是 **outlook.com 個人信箱**？
> 2. 業務是**每人各有自己的信箱**，還是共用**一個信箱**（例如 sales@）？
> 3. Microsoft 365 的管理員是誰？能不能協助在 Microsoft Entra 系統管理中心**註冊一個應用程式**，並同意它使用 **`Mail.Send`（委派權限）**？只需要寄信權限，不需要讀信權限。註冊應用程式不用另外付費。
> 4. 對外寄信有沒有**每日上限**、公司郵件政策，或是否會經過**郵件閘道／過濾設備**？
> 5. 公司網域的 **SPF、DKIM、DMARC** 是否已經設定？
>
> 謝謝！

## 為什麼要問這些
- 第 1 題：outlook.com 個人信箱已不能用密碼登入 SMTP（M2-25 實測 535），要走的路不同。
- 第 2 題：每人一個信箱 → 信從業務本人信箱寄出（ADR 0005 原設計）；共用信箱 → 要加「代表共用信箱寄出」的權限。
- 第 3 題：Graph 寄信一定要管理員註冊應用程式並同意 `Mail.Send`；這只有公司管理員能做。
- 第 4 題：決定系統的 `DAILY_SEND_LIMIT`、`SEND_PER_MINUTE` 要設多少，避免被公司或 Microsoft 限制。
- 第 5 題：影響信會不會進客戶的垃圾信件匣；若最後要用第三方轉發，必須先設定好。

## IT 回覆後的做法

| IT 的回答 | 做法 | 系統要做的事 |
|---|---|---|
| Microsoft 365，每人一個信箱，可以註冊應用程式 | Graph，從業務本人信箱寄（ADR 0005） | 管理員同意後填設定測試；程式改動很少 |
| Microsoft 365，一個共用信箱 | Graph＋共用信箱的「代表寄出」權限 | 小改寄件人設定，另寫 ADR |
| outlook.com 個人信箱 | Graph＋個人帳號（ADR 0007） | 做 M2-20、M2-21 |
| 不能註冊應用程式 | 第三方轉發（例如 Brevo）＋公司網域 SPF／DKIM | 加 `SMTP_FROM` 設定；先請公司確認客戶資料可交給外部服務 |

不建議正式寄客戶用 SMTP＋密碼：outlook.com 已停用，Microsoft 也在淘汰公司信箱（Exchange Online）的 SMTP 密碼登入。
